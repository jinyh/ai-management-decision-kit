# 案例：客户退款与补偿

> 课程合成情境。用于检验方法迁移，不对应真实企业。

一家消费品企业希望让AI处理客户退款与补偿。Agent可以读取订单、物流、产品政策和历史服务记录，并能在客服系统中生成回复、创建退款申请或发放补偿券。

## 新情况

- 订单显示已签收，但客户称未收到。
- 当前促销政策与下单时政策不同。
- 客户一年内已有多次补偿记录。
- 部分订单包含受限商品，退款规则不同。
- 自动退款可立即到账，补偿券可以撤销。

## 判断任务

1. 哪些信息属于当前上下文，哪些必须来自企业知识库？
2. 哪些冲突应由规则处理，哪些需要人工决定？
3. 对“生成回复、创建申请、实际退款、发券”分别判断允许、需批或停止。
4. 设计至少一个任务指标、经营指标和控制指标。
5. 写出发生系统异常或凭据泄露时的停止、接管和恢复顺序。

先完成自己的判断，再运行 `/authorize 客户退款与补偿`。不要让Agent直接代替企业制定退款政策。
