# 工具、连接协议与企业权限

## 管理结论

连接协议解决“怎样连接”，企业授权解决“谁可以在什么条件下做什么”。二者不能相互替代。

## 四层检查

1. **工具能力**：查询、计算、生成、提交或变更。
2. **身份与凭据**：工具以谁的身份运行，凭据何时失效。
3. **业务授权**：对象、金额、地区、时间和动作范围。
4. **运行证据**：实际调用、输入参数、返回结果和批准记录。

API通常比界面操作稳定、可审计；当旧系统没有合适接口时，可以有限使用计算机操作，但要加强界面变化检测、输入校验、截图或日志证据以及人工接管。

MCP、A2A等协议可以降低连接成本，但协议存在不代表企业已经完成身份、权限、审计和责任设计。

## 任务权限与环境隔离（P74）

任务授权规定这次允许做什么；环境隔离限制程序能接触哪些文件、网络和其他任务；凭据隔离限制它能以什么身份访问哪些系统。采购查询获准，不代表同一运行环境应能读取支付密钥。三者共同约束实际可执行范围，撤回业务批准时还需阻断排队动作并核对已经产生的外部结果。

## 自测

选择一个“提交订单”动作，分别写出读取权限、生成建议权限和真正提交权限由谁授予。

## A2P2的解释与范围

智能体自主支付协议（Agent Autonomous Payment Protocol，A2P2）可用“限定金额和购买范围、核对本次请求、保留结果证据”理解。[北京经开区2026-06-26报道](https://kfqgw.beijing.gov.cn/ywdt/gdcyfzgd/zncx/202606/t20260626_4726178.html)介绍京东的协议设计。报道不能证明它已成为全行业统一标准，也不能代替本企业对支付结果和授权的验证。核验2026-09-18。
