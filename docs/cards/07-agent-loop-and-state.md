# 智能体循环与任务状态

## 管理结论

智能体适合目标明确、路径需要根据环境调整、能够检查中间结果的多步任务。步骤固定、异常少、规则清楚的流程，普通自动化通常更容易控制。

## 完整工作循环

获取信息 → 规划步骤 → 调用工具 → 检查结果 → 处理失败 → 保存状态 → 继续、停止或请求人工决定。

真正需要管理的是整个运行过程：它读了什么、调用了什么、结果是否通过检查、失败后保存了什么状态、由谁批准继续。

## 三项边界

- 记住上一步，不等于获准做下一步。
- 能调用工具，不等于可以调用所有参数和对象。
- 自动重试不等于恢复；环境、凭据或输入受到污染时应先隔离和接管。

## 选择题

如果任务只有三步、规则稳定、每一步都可以确定验证，为什么还需要智能体？先回答这个问题，再讨论模型。

关联：[工具、协议与权限](08-tools-protocols-and-permissions.md)｜[人工授权与恢复](09-human-authorization-and-recovery.md)

## 模型选择与程序控制

模型依据当前证据提出下一工具调用；程序检查输入类型、对象范围和当前授权，执行后保存工具结果与检查点。任务状态、企业外部事实、授权状态分开维护。说明机制时展示可观察的工具输入输出与选择依据即可。

超时表示本地未收到结果，外部交易可能已经完成。先按请求标识核对：已创建则使用原回执；确认未创建且当前授权有效才考虑重试；持续未知则人工接管。外部服务必须支持同一业务请求的幂等去重，仅在本地记录一个编号不够。撤权应阻断后续调用，但不会自动撤销已经完成的外部交易。

简化串行算例：每一步在此前步骤成功条件下的成功率均为95%，十步且无重试时，整体约为0.95的10次方，即59.9%。条件概率连乘不要求独立，但不能未经检验就把十个边际成功率代入。

研究机制依据：[ReAct，2022](https://arxiv.org/abs/2210.03629)。持久化、授权与恢复是课程的企业系统设计归纳。

## 数据与学习的边界

运行中的“观察—行动—反馈”可以只执行既定策略；强化学习还要用奖励更新策略或行动回报估计，以改善后续行动。调用工具一次并不等于完成学习。参见[C15 强化学习、环境与奖励](15-reinforcement-learning-environments-rewards.md)。
