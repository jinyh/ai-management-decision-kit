# 买产品、联合实施、自建与FDE

## 管理结论

建设方式取决于差异化程度、系统复杂度、数据敏感性、内部能力和持续运营责任，不应由“是否先进”单独决定。

| 方式 | 更适合 | 主要风险 |
|---|---|---|
| 买产品 | 任务标准化、接口成熟 | 被产品边界限制，隐性集成成本 |
| 联合实施 | 业务差异明显、需要快速落地 | 知识留在供应商，责任边界模糊 |
| 自主建设 | 能力具有战略差异、团队成熟 | 建设和长期运营成本高 |

FDE（前线部署工程师）可以在现场把业务问题、数据、系统和模型连接成可运行流程，并快速暴露真实约束。FDE不是唯一角色，也不能替代业务负责人、数据责任人、平台团队、安全合规和运营团队。

## 管理决定

- 哪些知识与能力必须留在企业内部？
- 谁对上线后的评测、权限、故障和版本变化负责？
- 供应商退出后，企业能否继续运行、审计和修改？
- 试点结束时，是否已经形成可交接的对象、规则、测试和运行记录？

## FDE如何落实数据治理

业务问题 → 数据定义与质量要求 → 工程实现 → 业务验收与运行反馈。

| 角色 | 主要责任 | 可交付证据 |
|---|---|---|
| 业务负责人 | 确定目标、用途与授权 | 任务范围、放行和停止条件 |
| 数据负责人 | 维护定义、质量与责任 | 数据字典、主键映射规则、质量门槛 |
| FDE等工程人员 | 实现映射、连接与检查 | 可运行流程、测试记录、监控 |
| 运营人员 | 接管、维护并报告结果 | 运行台账、异常与恢复记录 |

FDE（前线部署工程师）是落实治理要求的一种实施角色，不替代企业责任人。角色依据：[Palantir官方岗位说明](https://jobs.lever.co/palantir/dab396d4-2f14-4796-aac0-0d82883dccf0)，核验2026-09-18；上述企业分工为课程归纳。交付时同时核对业务验收、数据口径、权限、测试、维护和恢复材料。
