# 任务型数据质量

## 管理结论

数据质量不是抽象的“干净程度”，而是数据能否支持一个具体任务。相同字段可能对财务结算足够，却不足以判断供应商是否迟交。

## 六项检查

| 检查 | 管理问题 |
|---|---|
| 准确 | 值是否与现实状态一致？ |
| 完整 | 作出当前决定所需证据是否齐全？ |
| 一致 | 系统、部门和时间口径是否相同？ |
| 及时 | 数据到达时，是否还来得及行动？ |
| 可追溯 | 能否找到来源、修改记录和责任人？ |
| 可使用 | 当前人员和AI是否拥有合法、有效的读取权限？ |

## 三项任务检验

先检查能不能识别对象，再检查能不能支持判断，最后检查能不能触发获准动作。主数据、日志、文档和经验规则都应服务于这三项检验。

## 特征、标签、训练与使用（P16）

以预测未来两周是否延迟为例：在预警时已经可见的“运输比计划慢2天、距承诺日还剩5天”是特征；两周后的实际交付结果是标签。训练用历史特征与结果学习模型参数；使用模型预测新订单时，还不知道其未来标签。训练材料只能使用预测当时可见的信息。

若预警后人工加急，最终准时，实际结果标签仍记为准时，并另记加急干预。我们没有同时观察这笔订单“不加急会怎样”，这个未发生的对照就是反事实。评估预警和干预的效果，需要可比对照，不能把“原本一定迟交”写成已知事实。

## 常见误判

- 把多个供应商编号一律当成脏数据，而不检查是否代表集团、法人和工厂不同层级。
- 追求所有字段一次治理完成，迟迟不能验证业务价值。
- 只修输入字段，不保留判断依据和运行结果。

## 数据与学习的边界

质量检查还应覆盖标签定义、样本选择、数据配比和独立测试集。将预警时证据、加急干预、实际准时结果分别保存；未经观察的反事实不能当成已知标签。参见[C13 主动学习与弱监督](13-active-learning-and-weak-supervision.md)与[C14 数据与学习信号](14-synthetic-data-demonstrations-preferences.md)。
