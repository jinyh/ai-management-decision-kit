# 区分上下文、企业知识和任务状态

## 管理结论

模型“知道很多”不等于它拥有当前有效的企业证据。企业需要区分六类内容，并给每类内容明确的来源、有效期和责任人。

| 内容 | 作用 | 主要风险 |
|---|---|---|
| 模型已有知识 | 通用语言与模式 | 过时、无法证明来源 |
| 当前上下文 | 当前任务材料与指令 | 缺页、冲突、超出窗口 |
| 企业知识库 | 制度、产品、合同模板、经验 | 版本与权限失控 |
| 任务状态/记忆 | 已完成步骤、结果、等待事项 | 把历史信息当成当前授权 |
| 知识图谱 | 对象和关系 | 关系正确但缺少行动规则 |
| Ontology | 类型、关系与语义约束 | 与业务执行及权限混淆 |

## 冲突处理

当合同、产品资料和内部制度冲突时，Agent不能自行选择“最像答案”的材料。应先根据适用对象、发布日期、合同优先级和责任岗位判断；无法解决时交还人工决定。

## 参数、上下文与上下文窗口（P34、P38）

参数是训练学到的数值，决定模型如何处理输入；上下文是这次运行交给模型的问题、材料和当前状态。给模型补充最新合同，会改变本次可用证据，通常不会改变参数。

Token是模型处理文本的片段单位，不等于一个汉字或一个单词；上下文窗口限制一次可处理的Token数量。能放进更多材料，不等于能可靠找到并正确使用其中每条证据。

## 自测

列出当前任务最关键的三份材料，并说明每份材料的责任人、有效期和允许谁读取。

关联：[主动检索](05-active-retrieval.md)｜[共同语言与Ontology](06-common-language-and-ontology.md)

## 数据进入AI系统的三条路径

参数知识适合通用模式与任务行为，改变通常需要训练。检索知识适合当前合同、制度和资料，更新需要同步片段、向量索引与版本。结构化查询适合订单、库存和聚合计算，正确性依赖主键、类型、单位和过滤条件。

微调不替代频繁变化的事实维护。删除原文也不保证派生向量、索引和缓存已同步删除。数据血缘需要标记哪些源记录影响了哪些派生数据、答案引用及历史行动。

研究依据：[Lewis等，RAG，2020](https://arxiv.org/html/2005.11401v4)。系统用途与生命周期建议是课程归纳。

## 本课程的知识库与学习教练Skill

知识库提供可引用的定义、案例和来源。学习教练Skill规定如何选卡、追问与输出。工具决定环境中能够执行什么操作。实际流程是：识别问题，读取两至三张卡，检查证据缺口，请学员修订判断。

例如，学员问“这项AI投资是否批准”，教练先读C03、C10、C12，区分错误代价、上线证据和投入范围。知识库网页是阅读入口；Skill需在支持它的智能体环境中运行。它只辅助学习，不代替业务审批。维护人审核修订，再用固定问题测试选卡、引用和输出，记录版本与回退依据。

参见[实际Skill文件](../../.agents/skills/ai-management-decision-coach/SKILL.md)。采购技能教学示例可以迁移相同结构：适用条件、取证步骤、例外处理与输出要求，不为示例虚构版本历史。

## 长上下文与检索实验的证据边界

2020年RAG实验用于说明怎样逐个检查组件，不代表当前模型性能。2026年位置控制研究在64K、GSM8K任务及两类干扰材料中仍观察到不同程度的位置影响，条件与数据见[长上下文专题](../frontier/context-position-20260918.md)。企业应按自己的任务、位置、材料与配置验证。
