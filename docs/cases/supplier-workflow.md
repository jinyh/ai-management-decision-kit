# 案例：供应商交付预警与行动

> 课程合成情境。公司、人物、金额和数据均不对应真实企业。

恒业集团希望减少关键物料迟交造成的停线。当前流程由采购人员汇总订单、合同、到货和物流信息，再决定是否联系供应商、调整计划或提交订单变更。

## 两项提案

| 维度 | 提案A：数据与知识平台 | 提案B：智能体流程 |
|---|---|---|
| 目标 | 统一对象、定义与证据 | 自动查询、判断并准备行动 |
| 投入 | 160万元，12周 | 160万元，12周 |
| 初步收益 | 减少找数与口径冲突 | 减少异常确认和跨系统操作 |
| 关键不确定性 | 是否能覆盖关键任务并形成责任机制 | 任务正确率、权限边界和接管成本 |

两项提案信息仍不足，不能仅凭描述选出“正确答案”。

## 分步任务

1. 先分别判断A、B：批准试点、补充证据、暂缓或拒绝。
2. 用[任务证据表](../../templates/task-evidence.md)写出经营结果和当前基线。
3. 参考[错误代价示例](../cards/03-error-cost-and-evaluation.md)，判断准确率以外还要什么证据。
4. 用[行动授权表](../../templates/action-authorization.md)划分查询、联系供应商、调整计划、修改合同和提交订单。
5. 用[投资备忘录](../../templates/investment-memo.md)写出下一道证据门。

## 迁移问题

如果供应商编号不一致来自“集团—法人—工厂”的合法层级，治理方案应该怎样变化？如果AI只能生成建议而不能提交订单，收益测算又应该怎样变化？
